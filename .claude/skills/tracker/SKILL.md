# Трекер цен

Обходит список ссылок, для каждой получает `{ regular_price, sale_price, has_credit }` по правилам скилла `extract-price` и сводит результаты в таблицу цен — запись прогона: одна строка на товар. Затем сравнивает её с прошлым прогоном, показывает **только значимые изменения** — по правилам из [`KNOWLEDGE.md`](KNOWLEDGE.md) — и присылает их сводкой в Telegram.

## Отслеживаемые URL

По умолчанию трекер проверяет этот список, поэтому для запуска хватит одной фразы: «запусти трекер». Чтобы отслеживать другую страницу, добавь или убери строку между маркерами: одна ссылка на строку, без рекламных меток.

<!-- urls:start -->
```text
https://www.onetwotrip.com/ru/aviabilety/MOW_MRV/
https://www.kupibilet.ru/aviabilety/iz-moskva/v-mineralnye-vody
https://biletyplus.ru/aviabilety/moskva-mow/mineralnye-vody-mrv
https://www.ozon.ru/travel/flight/moskva-mow/mineralnye-vody-mrv/
```
<!-- urls:end -->

## Вход

- **По умолчанию** — список из раздела «Отслеживаемые URL» выше. Ничего спрашивать у пользователя не нужно.
- **Если пользователь прислал свои ссылки**, проверь только их (разово, без изменения списка). Добавляй их в список, только если он прямо попросил «добавь в трекер».

## Шаги

1. **Подготовь список.** Убери дубликаты и рекламные метки (`utm_*`, `yclid`, `etext` и всё после `?`). Если ссылки пришли в сообщении, запиши их во временный файл, по одной на строку.

2. **Собери цены** одной командой:

   ```bash
   .claude/skills/tracker/scripts/collect.sh | tee "${TMPDIR:-/tmp}/run.jsonl"                 # список из этого SKILL.md
   .claude/skills/tracker/scripts/collect.sh /путь/к/списку | tee "${TMPDIR:-/tmp}/run.jsonl"  # свой список
   ```

   Запись сохраняется в `run.jsonl` — из неё на шагах 5 и 7 считается diff и собирается файл для `tracker-data`, второй раз сайты обходить не нужно.

   Для каждой ссылки скрипт загружает HTML и разбирает его парсером `extract-price/scripts/parse_price.py`. В stdout он печатает **запись прогона**, в stderr — предупреждения «⚠️ Цена не найдена: URL — причина». Ссылки обходятся по очереди. Если страница не ответила `200`, скрипт пробует ещё два раза с сохранёнными cookie, с паузами 3 и 10 секунд: всего до трёх попыток. Так разовые сбои сети (HTTP 000) и антибот-редиректы не попадают в запись как `null`.

   Если скрипт недоступен, пройди ссылки сам, применяя к каждой скилл `extract-price`, и составь запись в том же формате.

3. **Проверь каждую строку** по правилам `extract-price`. Например, главная `ozon.ru/travel/` — это не страница товара: число из такой страницы считай ненайденной ценой. Поставь в строке `regular_price: null` и добавь предупреждение.

4. **Прочитай прошлый прогон через GitHub MCP** — до сохранения нового:
   1. `get_file_contents` с `owner: LeeooBloom`, `repo: tracker-data`, `path: /`, `ref: main` — список файлов в корне.
   2. Оставь только файлы прогонов: имя по шаблону `YYYY-MM-DD.json` (`^\d{4}-\d{2}-\d{2}\.json$`). `README.md` и прочее пропусти.
   3. Отсортируй по имени (дата в имени, поэтому лексикографический порядок = хронологический) и возьми **последний**. Это и есть предыдущий прогон. Если сегодня уже был прогон, последним будет файл сегодняшнего дня: он и есть предыдущий.
   4. Прочитай его `get_file_contents` (`path: <имя>`, `ref: main`) и сохрани содержимое как есть в `${TMPDIR:-/tmp}/prev.json`.
   5. **Файлов прогонов нет** → это **первый запуск**, сравнивать не с чем. Переходи к шагу 7 и в ответе напиши «Первый прогон — сравнивать не с чем».

5. **Посчитай diff и примени правила значимости:**

   ```bash
   python3 -I .claude/skills/tracker/scripts/diff.py "${TMPDIR:-/tmp}/prev.json" "${TMPDIR:-/tmp}/run.jsonl" > "${TMPDIR:-/tmp}/diff.json"   # есть прошлый прогон
   python3 -I .claude/skills/tracker/scripts/diff.py - "${TMPDIR:-/tmp}/run.jsonl" > "${TMPDIR:-/tmp}/diff.json"                            # первый запуск
   ```

   Как считается diff:
   - товары сопоставляются **по `url`**;
   - для каждого товара, который есть в обоих прогонах, сравниваются поля `regular_price`, `sale_price`, `has_credit`, и по каждому отличию записывается событие: было → стало, разница в рублях и процентах;
   - URL только в текущем прогоне — **новый товар**, только в прошлом — **товар пропал**;
   - к каждому событию применяются правила из `KNOWLEDGE.md`: порог ±1 % и не меньше 10 ₽ для цен, скидка и рассрочка, новые и пропавшие товары, отдельная обработка «цена не получена».

   Скрипт печатает JSON (он сохраняется в `diff.json` для шага 8) с полями:
   - `changes` — **список изменений по каждому товару** (все отличия, со значимыми и незначимыми);
   - `significant` — только значимые изменения: **о них и уведомлять**;
   - `technical` — проблемы сбора (цена не получена / снова доступна): это не изменения цены;
   - `first_run` — `true`, если сравнивать не с чем.

   Если скрипт недоступен, посчитай то же самое вручную строго по `KNOWLEDGE.md`.

6. **Покажи результат** в формате раздела «Формат ответа»: **только значимые изменения**, а не весь список цен.

7. **Закоммить прогон через GitHub MCP** в репозиторий `tracker-data` как `YYYY-MM-DD.json` — по шагам раздела «Хранение». Запомни ссылку на коммит: она пойдёт в сообщение.

8. **Отправь сводку в Telegram** — это последний шаг прогона, по разделу «Уведомление в Telegram». Затем сообщи пользователю ссылку на коммит и результат отправки.

## Запись прогона

Запись прогона — **одна строка JSON на товар** (JSON Lines), в порядке списка. В каждой строке ровно четыре поля, в таком порядке:

| Поле | Тип | Значение |
|---|---|---|
| `url` | строка | Ссылка на страницу товара без рекламных меток. |
| `regular_price` | число или `null` | Обычная цена; `null`, если цена не найдена. |
| `sale_price` | число или `null` | Цена со скидкой; `null`, если скидки нет или цена не найдена. |
| `has_credit` | `true` / `false` | Есть ли на странице рассрочка или кредит. |

```jsonl
{"url": "https://www.onetwotrip.com/ru/aviabilety/MOW_MRV/", "regular_price": 3694, "sale_price": null, "has_credit": false}
{"url": "https://www.ozon.ru/travel/flight/moskva-mow/mineralnye-vody-mrv/", "regular_price": 3210, "sale_price": null, "has_credit": true}
```

Правила записи:

- Строка есть для **каждой** ссылки списка, даже если цена не найдена: тогда `regular_price` и `sale_price` равны `null`.
- В строку не добавляй других полей (`error`, `source`, дату и т. п.): запись — это будущий формат хранения прогона.
- Числа — без пробелов и символов валюты (`3694`, а не `"3 694 ₽"`).

Запись прогона сохраняется в `tracker-data` (раздел «Хранение»), но пользователю целиком **не выводится**: он видит только значимые изменения.

## Формат ответа

1. **Значимые изменения** — по одной строке на событие из `significant`, сгруппированные по товару. В строке — домен сайта (без `www.`), что изменилось, было → стало, разница:

   > **Значимые изменения с прогона 2026-11-11:**
   > - **onetwotrip.com** — цена снизилась: 3 990 → 3 694 ₽ (−296 ₽, −7,42 %)
   > - **ozon.ru** — скидка закончилась: было 3 000 ₽, теперь 3 210 ₽
   > - **biletyplus.ru** — рассрочка пропала

   Если значимых изменений нет: «Значимых изменений нет» и одной строкой — сколько незначимых отброшено (например, «2 колебания цены ниже порога ±1 %»).
   При первом запуске: «Первый прогон — сравнивать не с чем».

2. **Отброшено как незначимое** — одной строкой количество: незначимые изменения целиком не перечисляй.

3. **Технические события** из `technical` и каждая ссылка, по которой цена не найдена: «⚠️ Цена не найдена: `<URL>` — <причина>».

4. **Ссылка на коммит** прогона в `tracker-data`.

Весь список цен показывай, только если пользователь прямо попросил («покажи все цены»).


## Хранение

Один прогон — один файл в **корне** репозитория `LeeooBloom/tracker-data`:

- **Имя файла** — дата прогона: `YYYY-MM-DD.json`, например `2026-11-12.json`. Дату бери по московскому времени: `TZ=Europe/Moscow date +%F`.
- **Содержимое** — запись прогона в формате JSON: массив объектов с теми же четырьмя полями и в том же порядке, по одному на товар. Отступ 2 пробела, кириллица без экранирования, в конце перевод строки:

  ```json
  [
    {
      "url": "https://www.onetwotrip.com/ru/aviabilety/MOW_MRV/",
      "regular_price": 3694,
      "sale_price": null,
      "has_credit": false
    }
  ]
  ```

  Собери его из записи шага 2:

  ```bash
  python3 -I -c 'import json,sys; print(json.dumps([json.loads(l) for l in open(sys.argv[1], encoding="utf-8") if l.strip()], ensure_ascii=False, indent=2))' "${TMPDIR:-/tmp}/run.jsonl"
  ```

### Как закоммитить через GitHub MCP

Файл записывается **только инструментами GitHub MCP** (сервер `github`). Каждая запись файла через MCP — сразу отдельный коммит в репозитории. Поэтому **не делай `git clone`, `git commit` и `git push`** и не создавай локальную копию `tracker-data`.

1. **Проверь, есть ли уже файл этого дня:** `get_file_contents` с параметрами `owner: LeeooBloom`, `repo: tracker-data`, `path: YYYY-MM-DD.json`, `ref: main`.
   - Файл есть → запомни его `sha`: прогон этого дня будет перезаписан.
   - Ответ «не найден» → файл новый, `sha` не нужен.
2. **Проверь содержимое:** JSON читается, это массив, и в каждом объекте ровно поля `url, regular_price, sale_price, has_credit`.
3. **Запиши файл:** `create_or_update_file` с параметрами:

   | Параметр | Значение |
   |---|---|
   | `owner` | `LeeooBloom` |
   | `repo` | `tracker-data` |
   | `branch` | `main` |
   | `path` | `YYYY-MM-DD.json` (в корне, без папок) |
   | `content` | JSON из предыдущего шага, как текст |
   | `message` | `Run YYYY-MM-DD` |
   | `sha` | только если файл уже был (шаг 1) |

4. **Убедись, что коммит создан:** в ответе инструмента есть `commit.sha` / `commit.html_url`. Покажи пользователю ссылку на коммит и путь файла.

Если записать не удалось (сервер `github` не подключён — проверь `/mcp`; нет прав `Contents: Read and write` на `tracker-data`; ошибка API или конфликт `sha`), **сообщи пользователю** причину и выведи JSON файла, чтобы прогон не потерялся. Не делай вид, что прогон сохранён. Не пытайся обойти ошибку через локальный `git`.

## Уведомление в Telegram

Сводку собирает `summary.py` из `diff.json` шага 5, а отправляет `send.py` из корня репозитория:

```bash
MSG=$(python3 -I .claude/skills/tracker/scripts/summary.py "${TMPDIR:-/tmp}/diff.json" \
  --date "$(TZ=Europe/Moscow date +%F)" --prev-date <дата прошлого прогона> --commit-url <ссылка на коммит>)
python3 send.py "$MSG"
```

- `--prev-date` — дата из имени файла прошлого прогона (шаг 4); при первом запуске не передавай. `--commit-url` — ссылка из шага 7; если коммит не удался, не передавай.
- Сводка — **одна строка на значимое изменение**: домен сайта, что изменилось, было → стало, разница. Под ней — количество отброшенных незначимых изменений и технические события (⚠️ цена не получена).
- **Значимых изменений нет** → сообщение всё равно уходит: «Значимых изменений цен нет». Так видно, что прогон прошёл, а не сломался молча.
- Первый запуск → «Первый прогон — сравнивать не с чем».
- Токен и chat id `send.py` берёт из переменных окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` или из `.env` в корне (см. `.env.example`). Токен никогда не выводи.
- Успех — в выводе `Отправлено.` Иначе `send.py` печатает причину и завершается с ошибкой: передай её пользователю, покажи текст сводки в ответе и не делай вид, что уведомление ушло. Частые причины: пользователь не написал боту первым, неверный chat id, сеть облачного окружения не пускает на `api.telegram.org`.
